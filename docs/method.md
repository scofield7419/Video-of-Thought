# From the paper to the code

This note maps every component of *Video-of-Thought* (ICML 2024) to its
implementation, and records the decisions taken where the paper leaves details open.

## 1. Spatial-temporal scene graph (Sec. 3.2)

| Paper | Code |
|---|---|
| frames evenly sampled with a proper rate (8 fps for MotionEpic, Sec. 5.1) | `vot/video/io.py` — `load_video(fps=, max_frames=)`, `sample_timestamps` |
| single-frame SG `G_k = (V_k; E_k)` | `vot/stsg/schema.py` — `FrameGraph` |
| node `v_{k,i} = (c_i, f_i, b_i)` (label, neural feature, bbox) | `SGObject(id, bbox, label, feature)` |
| predicate edge `e_{k,i,j}` (subject–predicate–object) | `Triplet` |
| temporal coreference edge `e_{k-1→k}` ("tracking") | `CorefLink`; `STSG.infer_coref()`, `STSG.tracks()` |
| STSG expression generated by MotionEpic (Fig. 3) | `vot/stsg/expression.py` — `format_stsg` / `parse_stsg` |
| partial STSG = tracklet of targets (Step-2) | `STSG.subgraph(seeds, follow_tracks=True)` |
| "neighbor scenes" of the tracklet (Step-3) | `vot/stsg/ops.py` — `neighbor_scene(partial, full, hops)` |

Conventions fixed by this implementation (the paper does not specify them):

* frame numbers are 1-based positions in the sampled clip ("Frame 1" in Appendix A);
* boxes are `(x, y, w, h)` in **percent** of the frame size (resolution independent, short to generate);
* object ids are category names with a numeric suffix for multiple instances (`man-1`, `man-2`), as in Fig. 3.

The parser accepts the exact grammar of Fig. 3 as well as the deviations real
models produce (quotes, `[]` instead of `()`, code fences, missing coreference
section, JSON). It is covered by `tests/test_stsg.py`.

## 3. The VoT framework (Sec. 4, Fig. 4, Appendix A.1)

All prompts are in `vot/reasoning/prompts.py` (wording taken from the paper),
the orchestration in `vot/reasoning/vot.py`, the output parsers in
`vot/reasoning/parsing.py`.

| Step | Input (paper) | Output | Implementation |
|---|---|---|---|
| 1. Task definition & target identification | task definition (MC / open-ended; single / multiple answers), video, question | `[Target]` | `VideoOfThought.step1_targets` |
| 2. Object tracking | targets, video (+ STSG) | partial STSG `[Target Tracklet]` | `step2_tracking` (`generate` / `select` / `match`) |
| 3. Action analysing | tracklet + neighbour scenes in the STSG, commonsense | `[Observation and Implication]` | `step3_action` |
| 4-Pre. Open-ended → multiple choice | question, observation | k distinct candidates with scores | `step4_pre` |
| 4-A. Per-candidate scoring | question, candidate, observation | score (1–10) + rationale | `step4_rank` (parallel calls) |
| 4-B. Ranking | all scores | final answer | `step4_rank` |
| 5. Verification | video, STSG (pixel grounding), question, answer, observation | verdict + rationale | `step5_verify` |

Step-5 failure handling follows the paper: the rationale is recorded and Step-4
is re-executed (with the rejection reason appended to the scoring prompts) to
reselect the answer, up to `max_verify_rounds` times (previously rejected
candidates cannot be selected again). If no candidate passes verification
within this budget, the top-ranked answer of the first round is returned with
`verified=False`.

Ranking: "we rank the scores of all options and select the most optimal
answer". A unique score maximum is therefore authoritative; the Step-4-B
ranking prompt decides ties and covers unparsable scores (`ranking="model"`
always calls it, `"auto"` only when needed, `"score"` never).

Ablations of Table 4 (`w/o Verify-G`, `w/o Verify-C`) correspond to
`verify_perception=False` / `verify_cognition=False`
(`configs/vot/ablation_wo_verify_{g,c}.yaml`).

Baselines compared in the paper (direct answering and vanilla CoT, optionally
with STSG input as in "Video-LLaVA+STSG") are in `vot/reasoning/baselines.py`.

## 4. What the API version changes

MotionEpic is trained to generate grounded STSGs, so it runs VoT STSG-free.
For general-purpose API models the reasoning chain is unchanged; only the
realisation of the two non-text modalities differs:

* **video** → sampled frames sent as images, each captioned `Frame k (t=…s)` so
  that STSG frame numbers refer to them;
* **STSG** → its textual expression; models that were not trained on the
  grammar additionally receive a compact specification (`STSG_FORMAT_SPEC`).

Because API models localise objects poorly, Step-2 can optionally be anchored
to an explicit STSG from an *STSG provider* (`vot/grounding/`): annotated
graphs, a VLM parse of the full STSG (the prompting analogue of the L2
objective), or an open-vocabulary detector + IoU tracker. See
[api_version.md](api_version.md).
